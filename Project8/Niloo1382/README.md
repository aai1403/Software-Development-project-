# Bug Report Documentation
اعضای گروه:نیلوفر قاسمی و بهنوش عبدی

این پروژه به مستندسازی مشکلات و فرآیند گزارش باگ (Bug Reporting) می‌پردازد.

## چگونه یک گزارش باگ خوب بنویسیم؟

یک گزارش خوب باید سه بخش اصلی داشته باشد:

### ۱. عنوان واضح و مشخص (Clear Title)
عنوان باید دقیقاً مشکل را توصیف کند. از عناوین مبهم مثل "کار نمی‌کند" خودداری کنید.
- بد: "باگ در صفحه"
- خوب: "دکمه ثبت‌نام در موبایل پاسخ نمی‌دهد"

### ۲. مراحل بازتولید (Steps to Reproduce)
دقیقاً بنویسید چه کارهایی انجام دادید تا باگ ظاهر شود.
۱. صفحه ورود را باز کنید
۲. رمز عبور اشتباه وارد کنید
۳. روی دکمه ورود کلیک کنید

### ۳. رفتار مورد انتظار و رفتار واقعی (Expected vs Actual)
- Expected: قرار بود چه اتفاقی بیفتد؟
- Actual: در عمل چه اتفاقی افتاد؟

## قالب ایشو (Issue Template)
این ریپازیتوری شامل یک قالب استاندارد برای گزارش باگ در مسیر .github/ISSUE_TEMPLATE/bug_report.md است.
